Вариант 1 1. Концептуальная модель User — пользователь образовательной платформы; Course — онлайн-курс; Lesson — урок, входящий в состав курса; Enrollment — запись пользователя на курс; Review — отзыв пользователя о курсе.
Концептуальная модель показывает основные сущности и связи между ними без детализации атрибутов.

Основные связи:

один преподаватель может создавать несколько курсов; один курс состоит из нескольких уроков; пользователь может записаться на несколько курсов; на один курс могут записаться несколько пользователей; пользователь может оставлять отзывы; один курс может иметь несколько отзывов.

Логическая модель
На этапе построения логической модели для каждой сущности были определены атрибуты, первичные и внешние ключи, а также кардинальности связей.

User

Основные атрибуты:

user_id — первичный ключ; email — электронная почта пользователя; full_name — имя пользователя; role — роль пользователя; created_at — дата регистрации.

Поле email должно быть уникальным, поскольку два пользователя не должны иметь один и тот же адрес электронной почты.

Course

Основные атрибуты:

course_id — первичный ключ; title — название курса; description — описание; price — стоимость курса; instructor_id — внешний ключ на User; created_at — дата создания курса.

instructor_id связывает курс с преподавателем.

Связь:

User 1 : N Course

Один преподаватель может создать несколько курсов, но каждый курс имеет одного преподавателя.

Lesson

Основные атрибуты:

lesson_id — первичный ключ; course_id — внешний ключ на Course; title — название урока; order_num — порядковый номер урока; duration_min — продолжительность урока в минутах.

Связь:

Course 1 : N Lesson

Один курс может содержать несколько уроков, а каждый урок относится к одному курсу.

Атрибут order_num необходим для определения правильного порядка прохождения уроков.

Enrollment

Основные атрибуты:

enrollment_id — первичный ключ; course_id — внешний ключ на Course; user_id — внешний ключ на User; enrolled_at — дата записи на курс; completed_at — дата завершения; progress — процент прохождения курса.

Связи:

User 1 : N Enrollment

Course 1 : N Enrollment

Review

Основные атрибуты:

review_id — первичный ключ; course_id — внешний ключ на Course; user_id — внешний ключ на User; rating — оценка курса; comment — текст отзыва; created_at — дата создания отзыва.

Связи:

User 1 : N Review

Course 1 : N Review

Один пользователь может оставить отзывы на разные курсы, а один курс может иметь несколько отзывов.

Внешние ключи

Для обеспечения связности данных используются forein key:

Таблица Внешний ключ Ссылается на Course instructor_id User.user_id Lesson course_id Course.course_id Enrollment course_id Course.course_id Enrollment user_id User.user_id Review course_id Course.course_id Review user_id User.user_id

Forein key необходимы для того, чтобы записи в дочерних таблицах всегда ссылались на существующие записи в родительских таблицах.

Кардинальности User — Course: 1:N Course — Lesson: 1:N User — Enrollment: 1:N Course — Enrollment: 1:N User — Review: 1:N Course — Review: 1:N

Идентифицирующие и неидентифицирующие связи

Все основные связи в модели являются неидентифицирующими.

Это связано с тем, что дочерние сущности имеют собственные первичные ключи. Например, Lesson имеет собственный lesson_id, а course_id является только внешним ключом.

Аналогично:

Enrollment имеет собственный enrollment_id; Review имеет собственный review_id; Lesson имеет собственный lesson_id.

Физическая модель
Физическая модель реализует логическую модель в PostgreSQL.

Для каждой сущности создаётся отдельная таблица. Для идентификаторов используются SERIAL, для строковых данных — VARCHAR, для больших текстовых описаний — TEXT, для числовых значений — INTEGER и DECIMAL, для дат — TIMESTAMP.

Для каждой таблицы определён первичный ключ PRIMARY KEY.

Для реализации связей между таблицами используются внешние ключи FOREIGN KEY.

Также используются ограничения:

NOT NULL — для обязательных атрибутов; UNIQUE — для значений, которые должны быть уникальными; CHECK — для проверки допустимых значений.
